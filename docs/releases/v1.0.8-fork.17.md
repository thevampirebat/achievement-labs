# Achievement Labs unofficial fork — mobile update .17

This is an independently maintained, unofficial fork of [Achievement-Labs/achievement-labs](https://github.com/Achievement-Labs/achievement-labs).

Feature contribution: [upstream PR #15](https://github.com/Achievement-Labs/achievement-labs/pull/15), which remains open and unmerged. App updates/downloads use the vampirebat fork; event JSON/catalogue updates continue to use Achievement Labs.

## Android 0.6.12 (version code 20) — changes since fork .16 / Android 0.6.8

- Show event-token expiry and estimated time remaining using Xbox's issuer-provided expiry. Expiry is bound to the exact saved token; imported/replaced tokens without matching metadata show unknown expiry.
- Keep Scan QR accessible throughout the main app pages and Xbox 360 editor, with existing automatic sign-in, event-token and saved-queue recognition.
- Harden credential QR imports so only validated transfer fields enter account state. Preserve account, game/edition and active-queue checks; scans never start unlocking.
- Keep the established account-authorization spoofing flow and clearer guidance to scan the PC app's full sign-in QR when heartbeat authorization is refused. Event-token-only sync does not replace spoofing authorization.
- Remove obsolete experimental presence fields without deleting the saved account, renewal credentials or event token.
- Retain phone-only Microsoft sign-in and event-token acquisition.
- Signed with the established Android release certificate for an update over the existing installation.

## iOS 0.12.15 (build 33) — changes since fork .16 / iOS 0.12.10

- Add the same issuer-bound event-token expiry/time-remaining display, including unknown/expired states and preservation through credential renewal.
- Make Scan QR available throughout the app, including the Xbox 360 editor; retain automatic QR-type recognition and import confirmations.
- Require a user gesture for media playback in embedded Microsoft sign-in, prefer inline playback, and disable Picture in Picture and AirPlay there. This addresses the unwanted black media-player presentation; the live two-factor prompt still needs a physical-device check.
- Keep the existing PC-transferred/manual authorization flow for spoofing and remove the unsuccessful phone-only presence experiments. Phone-only event-token acquisition remains available.
- Retain sanitized presence diagnostics, including correlation/server codes where available, without exposing tokens or raw authentication responses.
- Discard obsolete experimental presence state while preserving the account and event token.
- The IPA is unsigned and requires your normal signing/sideloading method. iOS/iPadOS 17 or later.

## Using this update

Install over the previous version to preserve app data. For mobile spoofing, scan the Windows app's full sign-in QR for the same account; a phone-only browser login or event-token-only transfer does not provide proven heartbeat permission.

The event-token countdown reflects the issuer's expiry, not a guarantee the service will accept the token until that time. Tokens can be rejected earlier. Imported tokens without issuer metadata correctly show unknown expiry.
